## 项目概述

校园招聘系统是一个基于 Spring Cloud 微服务架构的招聘管理平台，采用前后端分离设计。系统支持学生求职、企业招聘、管理员监管等功能，实现校园招聘全流程管理。

### 系统特点
- **微服务架构**：采用 Spring Cloud 技术栈
- **API 网关**：Spring Cloud Gateway 统一入口，实现路由转发和身份认证
- **角色分离**：按用户角色划分为三个业务服务（管理员、学生、企业）
- **文件存储**：使用 MinIO 实现文件存储服务
- **异步处理**：使用 RabbitMQ 实现消息通知、简历投递通知等异步处理
- **缓存优化**：Redis 缓存热点数据
- **配置管理**：配置文件直接写在 yml 中，不使用注册中心

## 模块详细分析

### 1. hiring-gateway（网关服务）

#### 功能职责
- **统一入口**：所有外部请求的统一入口点
- **路由转发**：根据路由规则将请求转发到对应的微服务
- **身份认证**：JWT Token 验证，实现统一认证
- **权限控制**：区分管理员、学生、企业三种角色权限
- **白名单管理**：配置不需要认证的接口（如登录、注册接口）

#### 核心组件
- **HiringGatewayApplication**: 网关启动类
- **AuthFilter**: 全局认证过滤器
  - 从请求头获取 JWT Token
  - 验证 Token 有效性
  - 检查 Redis 中的登录状态
  - 验证用户身份（管理员/学生/企业）
  - 白名单路径跳过认证

#### 配置说明
- 配置文件：`application.yml`
- 路由规则在配置文件中静态配置
- 不使用服务注册中心，直接配置服务地址

#### 技术实现
```java
@Order(1)
public class AuthFilter implements GlobalFilter, Ordered {
    // 1. 检查白名单
    // 2. 提取 Token
    // 3. 验证 Token
    // 4. 检查 Redis 登录状态
    // 5. 验证用户身份权限（管理员/学生/企业）
}
```

#### 路由规则配置
```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: hiring-admin
          uri: http://localhost:8081
          predicates:
            - Path=/admin/**
        - id: hiring-student
          uri: http://localhost:8082
          predicates:
            - Path=/student/**
        - id: hiring-enterprise
          uri: http://localhost:8083
          predicates:
            - Path=/enterprise/**
```

## 模块间通信机制

### 1. API 网关路由（Spring Cloud Gateway）

#### 路由转发流程
```
客户端请求 
  → Gateway (统一入口)
    → 身份认证 (AuthFilter)
      → 路由转发到对应服务
        → 服务处理请求
          → 返回响应
```

#### 路由规则
路由规则在配置文件中静态配置，不使用服务注册中心：
```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: hiring-admin
          uri: http://localhost:8081
          predicates:
            - Path=/admin/**
        - id: hiring-student
          uri: http://localhost:8082
          predicates:
            - Path=/student/**
        - id: hiring-enterprise
          uri: http://localhost:8083
          predicates:
            - Path=/enterprise/**
```

### 2. 同步调用（OpenFeign）

#### 使用场景
- **hiring-student → hiring-enterprise**: 学生查看职位详情、提交咨询
- **hiring-enterprise → hiring-student**: 企业查看学生信息、提交咨询
- **hiring-admin → hiring-student/hiring-enterprise**: 管理员管理用户信息

#### 实现方式
```java
// hiring-api 模块定义接口
@FeignClient(value = "hiring-enterprise", url = "http://localhost:8083")
public interface RemoteEnterpriseService {
    @GetMapping("/enterprise/job/{jobId}")
    R<JobVO> getJobById(@PathVariable Long jobId);
}

// hiring-student 模块使用
@Autowired
private RemoteEnterpriseService remoteEnterpriseService;

public R<JobVO> getJobDetail(Long jobId) {
    return remoteEnterpriseService.getJobById(jobId);
}
```

#### 调用流程
```
hiring-student 服务
  → 调用 RemoteEnterpriseService
    → Feign 客户端
      → 直接 HTTP 调用 hiring-enterprise 服务（配置的 URL）
        → 返回结果
```

### 3. 异步消息（RabbitMQ）

#### 使用场景
- **简历投递通知**：学生投递简历后，通知企业有新简历
- **消息通知**：面试通知、申请状态变更通知等

#### 消息队列
- **简历投递通知队列**: `resume-delivery-queue`
- **消息通知队列**: `message-notify-queue`

#### 实现方式

##### 生产者（hiring-student - 简历投递）
```java
@Component
public class ResumeDeliveryProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    public void sendResumeDeliveryNotification(ResumeDeliveryDTO deliveryDTO) {
        rabbitTemplate.convertAndSend(
            RabbitMQConstants.RESUME_DELIVERY_QUEUE, 
            deliveryDTO
        );
    }
}
```

##### 消费者（hiring-enterprise - 简历投递通知）
```java
@Component
public class ResumeDeliveryConsumer {
    @Autowired
    private IResumeService resumeService;
    
    @RabbitListener(queues = RabbitMQConstants.RESUME_DELIVERY_QUEUE)
    public void consume(ResumeDeliveryDTO deliveryDTO) {
        resumeService.notifyNewResume(deliveryDTO);
    }
}
```

##### 生产者（消息通知）
```java
@Component
public class MessageProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    public void sendMessage(MessageDTO messageDTO) {
        rabbitTemplate.convertAndSend(
            RabbitMQConstants.MESSAGE_NOTIFY_QUEUE, 
            messageDTO
        );
    }
}
```

#### 消息流转流程
```
简历投递流程：
学生投递简历
  → hiring-student 保存投递记录
    → Producer 发送消息到 RabbitMQ（简历投递通知队列）
      → 立即返回（异步处理）
        → hiring-enterprise Consumer 消费消息
          → 企业收到新简历通知

消息通知流程：
系统事件触发
  → Producer 发送消息到 RabbitMQ（消息通知队列）
    → Consumer 消费消息
      → 保存消息到数据库
        → 通知用户
```

### 4. 缓存通信（Redis）

#### 使用场景
- **JWT Token 存储**：存储用户登录状态
- **热点数据缓存**：职位信息、用户信息、统计数据等
- **分布式锁**：防止并发问题（如职位申请、面试安排等）

#### 缓存管理
各模块通过 `RedisService` 统一操作 Redis：
```java
// 存储 Token
redisService.setCacheObject(tokenKey, loginUser, expireTime);

// 获取 Token
LoginUser user = redisService.getCacheObject(tokenKey, LoginUser.class);

// 检查登录状态
boolean isLogin = redisService.hasKey(tokenKey);

// 缓存职位信息
redisService.setCacheObject(jobKey, jobInfo, 3600);

// 获取缓存
JobVO job = redisService.getCacheObject(jobKey, JobVO.class);
```

#### 缓存键命名规范
- **用户Token**: `token:{userKey}`
- **职位信息**: `job:{jobId}`
- **用户信息**: `user:{userId}`
- **统计数据**: `statistics:{type}:{date}`

## 数据流转流程

### 1. 用户登录流程

```
1. 用户提交登录信息（学生/企业/管理员）
   ↓
2. 请求到达 Gateway
   ↓
3. Gateway 检查白名单（登录接口在白名单中，跳过认证）
   ↓
4. 路由转发到对应服务（hiring-student/hiring-enterprise/hiring-admin）
   ↓
5. 服务验证用户名密码
   ↓
6. 生成 JWT Token（包含用户ID、用户Key、角色）
   ↓
7. 将 Token 和用户信息存储到 Redis
   ↓
8. 返回 Token 给客户端
```

```
1. 企业发布职位
   ↓

   ↓
3. 路由转发到 hiring-enterprise
   ↓
4. hiring-enterprise 保存职位信息（状态：待审核）
   ↓
```

## 核心功能实现

### 1. 身份认证与授权

#### JWT Token 生成
```java
// 登录成功后生成 Token
String token = JwtUtils.createToken(userId, userKey, role);
// Token 包含：用户ID、用户Key、角色（ADMIN/STUDENT/ENTERPRISE）
```

#### Token 验证（Gateway）
```java
// 1. 从请求头获取 Token
String token = getToken(request);

// 2. 解析 Token
Claims claims = JwtUtils.parseToken(token, secret);

// 3. 检查 Redis 中的登录状态
String userKey = JwtUtils.getUserKey(claims);
boolean isLogin = redisService.hasKey(getTokenKey(userKey));

// 4. 验证用户身份权限
LoginUser user = redisService.getCacheObject(getTokenKey(userKey), LoginUser.class);
String path = request.getPath().value();

// 管理员接口只能管理员访问
if (path.startsWith("/admin/") && !UserRole.ADMIN.equals(user.getRole())) {
    return unauthorizedResponse(exchange, "权限不足");
}

// 学生接口只能学生访问
if (path.startsWith("/student/") && !UserRole.STUDENT.equals(user.getRole())) {
    return unauthorizedResponse(exchange, "权限不足");
}

// 企业接口只能企业访问
if (path.startsWith("/enterprise/") && !UserRole.ENTERPRISE.equals(user.getRole())) {
    return unauthorizedResponse(exchange, "权限不足");
}
```

#### 权限控制
- **管理员接口**（`/admin/**`）：仅管理员可访问
- **学生接口**（`/student/**`）：仅学生可访问
- **企业接口**（`/enterprise/**`）：仅企业可访问
- **白名单接口**：登录、注册等接口不需要认证

### 2. 职位推荐实现

#### 推荐策略（简单匹配）
职位推荐采用简单的同步查询方式，不使用复杂的推荐算法和异步处理：

```java
// 1. 获取学生信息（专业、技能、经验等）
Student student = getStudentById(studentId);

// 2. 根据学生条件查询匹配的职位（同步查询）
List<Job> recommendedJobs = jobMapper.selectList(
    new LambdaQueryWrapper<Job>()
        .eq(Job::getStatus, JobStatus.APPROVED)  // 已审核通过的职位
        .eq(Job::getRequiredMajor, student.getMajor())  // 专业匹配
        .le(Job::getRequiredExperience, student.getExperience())  // 经验要求
        .ge(Job::getSalary, student.getExpectedSalary())  // 薪资匹配
        .orderByDesc(Job::getCreateTime)  // 按发布时间排序
        .last("LIMIT 20")  // 限制返回数量
);

// 3. 返回推荐结果（可选：缓存到Redis）
return recommendedJobs;
```

#### 推荐逻辑说明
- **专业匹配**：优先推荐与学生专业相符的职位
- **经验匹配**：推荐经验要求不超过学生经验的职位
- **薪资匹配**：推荐薪资不低于学生期望的职位
- **时间排序**：按职位发布时间倒序，优先显示最新职位
- **简单高效**：直接数据库查询，无需复杂的推荐算法

### 3. 人才推荐实现

#### 推荐策略（简单匹配）
人才推荐采用简单的同步查询方式，不使用复杂的推荐算法和异步处理：

```java

        .ge(Student::getExperience, job.getRequiredExperience())  // 经验匹配
        .le(Student::getExpectedSalary, job.getSalary())  // 薪资期望匹配
        .orderByDesc(Student::getCreateTime)  // 按注册时间排序
        .last("LIMIT 20")  // 限制返回数量
```

#### 推荐逻辑说明

- **经验匹配**：推荐经验满足职位要求的学生
- **薪资匹配**：推荐薪资期望不超过职位薪资的学生

### 4. 缓存策略

#### 缓存使用场景
- **用户登录状态**：Token 对应的用户信息（过期时间：2小时）
- **职位数据**：热点职位信息（过期时间：1小时）
- **用户信息**：用户基本信息（过期时间：30分钟）
- **统计数据**：运营统计数据（过期时间：1天）

#### 缓存更新策略
- **写操作**：更新数据库后清除相关缓存
- **读操作**：先查缓存，缓存未命中再查数据库
- **过期时间**：根据数据特性设置不同的过期时间
- **缓存预热**：系统启动时预热热点数据

#### 缓存清除示例
```java
// 职位更新后清除缓存
public void updateJob(Job job) {
    // 1. 更新数据库
    jobMapper.updateById(job);
    
    // 2. 清除相关缓存
    redisService.deleteObject("job:" + job.getId());
    redisService.deleteObject("job:list:*");
    
    // 3. 如果职位状态变更，清除推荐缓存
    if (job.getStatus() != oldStatus) {
        redisService.deleteObject("recommend:job:*");
    }
}
```
