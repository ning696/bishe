## 项目概述

QD-OJ 是一个基于 Spring Cloud 微服务架构的在线判题系统（Online Judge），采用前后端分离设计。系统支持用户在线提交代码、自动判题、竞赛管理、消息通知等功能。

### 系统特点
- **微服务架构**：采用 Spring Cloud Alibaba 技术栈
- **服务注册与发现**：使用 Nacos 作为注册中心和配置中心
- **API 网关**：Spring Cloud Gateway 统一入口，实现路由转发和身份认证
- **异步处理**：使用 RabbitMQ 实现代码判题的异步处理
- **代码沙箱**：基于 Docker 实现安全的代码执行环境
- **缓存优化**：Redis 缓存热点数据
- **全文搜索**：Elasticsearch 支持题目搜索

## 模块详细分析

### 1. oj-gateway（网关服务）

#### 功能职责
- **统一入口**：所有外部请求的统一入口点
- **路由转发**：根据路由规则将请求转发到对应的微服务
- **身份认证**：JWT Token 验证，实现统一认证
- **权限控制**：区分管理员（B端）和普通用户（C端）权限
- **白名单管理**：配置不需要认证的接口（如登录接口）

#### 核心组件
- **OjGatewayApplication**: 网关启动类
- **AuthFilter**: 全局认证过滤器
  - 从请求头获取 JWT Token
  - 验证 Token 有效性
  - 检查 Redis 中的登录状态
  - 验证用户身份（管理员/普通用户）
  - 白名单路径跳过认证

#### 配置说明
- 使用 Nacos 作为配置中心
- 配置文件：`bootstrap.yml`
- 路由规则在 Nacos 配置中心动态配置

#### 技术实现
```java
@Order(1)
public class AuthFilter implements GlobalFilter, Ordered {
    // 1. 检查白名单
    // 2. 提取 Token
    // 3. 验证 Token
    // 4. 检查 Redis 登录状态
    // 5. 验证用户身份权限
}
```

### 4. oj-judge（判题服务模块）

#### 功能职责
- **代码判题**：接收代码提交，执行判题逻辑
- **代码执行**：在 Docker 沙箱中安全执行用户代码
- **结果比对**：比对用户输出和预期输出
- **资源限制**：限制代码执行的内存、CPU、时间

#### 核心功能模块

##### 4.1 判题服务（JudgeService）
- **判题流程**：
  1. 接收判题请求（`JudgeSubmitDTO`）
  2. 在 Docker 沙箱中执行代码
  3. 编译代码（Java）
  4. 运行代码，获取输出
  5. 比对输出结果
  6. 检查时间、内存限制
  7. 计算得分
  8. 保存判题结果

##### 4.2 沙箱服务（SandboxService）
- **Docker 集成**：使用 Docker Java API 创建容器
- **代码执行**：
  - 创建用户代码文件
  - 在 Docker 容器中编译代码
  - 执行代码并获取输出
  - 清理容器和临时文件
- **资源限制**：
  - 内存限制（默认 100MB）
  - CPU 限制（默认 1 核）
  - 执行时间限制（默认 5 秒）

##### 4.3 沙箱池服务（SandboxPoolService）
- **连接池管理**：管理 Docker 沙箱连接池
- **性能优化**：复用 Docker 容器，提高判题效率

##### 4.4 消息消费（JudgeConsumer）
- **RabbitMQ 消费**：监听 `oj-work-queue` 队列
- **异步判题**：消费消息后执行判题逻辑

#### 技术实现
```java
// 判题流程
1. 创建用户代码文件
2. 初始化 Docker 沙箱
3. 编译代码（javac）
4. 执行代码（java），传入测试用例
5. 收集输出结果
6. 比对输出和预期结果
7. 检查时间和内存限制
8. 计算得分并保存结果
```

### 2. API 网关路由（Spring Cloud Gateway）

#### 路由转发流程
```
客户端请求 
  → Gateway (统一入口)
    → 身份认证 (AuthFilter)
      → 路由转发到对应服务
        → 服务处理请求
          → 返回响应
```

#### 路由规则
路由规则在 Nacos 配置中心配置，示例：
```yaml
spring:
  cloud:
    gateway:
      routes:
        - id: oj-system
          uri: lb://oj-system
          predicates:
            - Path=/system/**
        - id: oj-friend
          uri: lb://oj-friend
          predicates:
            - Path=/friend/**
        - id: oj-judge
          uri: lb://oj-judge
          predicates:
            - Path=/judge/**
```

#### 负载均衡
- 使用 Spring Cloud LoadBalancer 实现服务负载均衡
- 支持多实例部署

### 3. 同步调用（OpenFeign）

#### 使用场景
- **oj-friend → oj-judge**: 同步判题调用
- 需要立即获取结果的场景

#### 实现方式
```java
// oj-api 模块定义接口
@FeignClient(value = Constants.JUDGE_SERVICE)
public interface RemoteJudgeService {
    @PostMapping("/judge/doJudgeJavaCode")
    R<UserQuestionResultVO> doJudgeJavaCode(@RequestBody JudgeSubmitDTO judgeSubmitDTO);
}

// oj-friend 模块使用
@Autowired
private RemoteJudgeService remoteJudgeService;

public R<UserQuestionResultVO> submit(UserSubmitDTO submitDTO) {
    JudgeSubmitDTO judgeSubmitDTO = assembleJudgeSubmitDTO(submitDTO);
    return remoteJudgeService.doJudgeJavaCode(judgeSubmitDTO);
}
```

#### 调用流程
```
oj-friend 服务
  → 调用 RemoteJudgeService
    → Feign 客户端
      → 通过 Nacos 服务发现找到 oj-judge 服务
        → HTTP 调用 oj-judge 接口
          → 返回结果
```

### 4. 异步消息（RabbitMQ）

#### 使用场景
- **oj-friend → oj-judge**: 异步判题（提高响应速度）
- 高并发场景下的代码提交

#### 消息队列
- **队列名称**: `oj-work-queue`
- **消息格式**: JSON（`JudgeSubmitDTO`）

#### 实现方式

##### 生产者（oj-friend）
```java
@Component
public class JudgeProducer {
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    public void produceMsg(JudgeSubmitDTO judgeSubmitDTO) {
        rabbitTemplate.convertAndSend(
            RabbitMQConstants.OJ_WORK_QUEUE, 
            judgeSubmitDTO
        );
    }
}
```

##### 消费者（oj-judge）
```java
@Component
public class JudgeConsumer {
    @Autowired
    private IJudgeService judgeService;
    
    @RabbitListener(queues = RabbitMQConstants.OJ_WORK_QUEUE)
    public void consume(JudgeSubmitDTO judgeSubmitDTO) {
        judgeService.doJudgeJavaCode(judgeSubmitDTO);
    }
}
```

#### 消息流转流程
```
用户提交代码
  → oj-friend 接收请求
    → JudgeProducer 发送消息到 RabbitMQ
      → 立即返回（异步处理）
        → oj-judge 消费消息
          → 执行判题逻辑
            → 保存判题结果
```

## 数据流转流程

### 1. 用户登录流程

```
1. 用户提交登录信息
   ↓
2. 请求到达 Gateway
   ↓
3. Gateway 检查白名单（登录接口在白名单中，跳过认证）
   ↓
4. 路由转发到 oj-system 或 oj-friend
   ↓
5. 服务验证用户名密码
   ↓
6. 生成 JWT Token
   ↓
7. 将 Token 和用户信息存储到 Redis
   ↓
8. 返回 Token 给客户端
```

### 2. 代码提交与判题流程（同步）

```
1. 用户提交代码
   ↓
2. Gateway 身份认证（验证 Token）
   ↓
3. 路由转发到 oj-friend
   ↓
4. oj-friend 接收请求
   ↓
5. 通过 Feign 调用 oj-judge 服务
   ↓
6. oj-judge 执行判题：
   - 创建 Docker 容器
   - 编译代码
   - 执行代码
   - 比对结果
   ↓
7. 返回判题结果
   ↓
8. oj-friend 保存提交记录
   ↓
9. 返回结果给客户端
```

### 3. 代码提交与判题流程（异步）

```
1. 用户提交代码
   ↓
2. Gateway 身份认证
   ↓
3. 路由转发到 oj-friend
   ↓
4. oj-friend 接收请求
   ↓
5. 发送消息到 RabbitMQ（oj-work-queue）
   ↓
6. 立即返回（提交成功，判题中...）
   ↓
7. oj-judge 消费消息
   ↓
8. 执行判题逻辑
   ↓
9. 保存判题结果到数据库
```

### 4. 管理员管理题目流程

```
1. 管理员登录（获取 Token）
   ↓
2. 创建/编辑题目
   ↓
3. Gateway 验证管理员身份
   ↓
4. 路由转发到 oj-system
   ↓
5. oj-system 保存题目到数据库
   ↓
6. 同步题目数据到 Elasticsearch（用于搜索）
   ↓
7. 清除相关缓存
   ↓
8. 返回操作结果
```

### 5. 竞赛结束处理流程

```
1. XXL-Job 定时任务触发
   ↓
2. 查询已结束的竞赛
   ↓
3. 计算用户竞赛成绩
   ↓
4. 生成排行榜
   ↓
5. 发送竞赛结束通知消息
   ↓
6. 更新竞赛状态
   ↓
7. 更新缓存
```

## 核心功能实现

### 1. 身份认证与授权

#### JWT Token 生成
```java
// 登录成功后生成 Token
String token = JwtUtils.createToken(userId, userKey, identity);
// Token 包含：用户ID、用户Key、身份（管理员/普通用户）
```

#### Token 验证（Gateway）
```java
// 1. 从请求头获取 Token
String token = getToken(request);

// 2. 解析 Token
Claims claims = JwtUtils.parseToken(token, secret);

// 3. 检查 Redis 中的登录状态
String userKey = JwtUtils.getUserKey(claims);
boolean isLogin = redisService.hasKey(getTokenKey(userKey));

// 4. 验证用户身份权限
LoginUser user = redisService.getCacheObject(getTokenKey(userKey), LoginUser.class);
if (url.contains("/system/") && !UserIdentity.ADMIN.equals(user.getIdentity())) {
    return unauthorizedResponse(exchange, "权限不足");
}
```

#### 权限控制
- **B端接口**（`/system/**`）：仅管理员可访问
- **C端接口**（`/friend/**`）：普通用户和管理员都可访问
- **白名单接口**：登录、注册等接口不需要认证

### 2. 代码沙箱执行

#### Docker 沙箱实现
```java
// 1. 创建用户代码文件
createUserCodeFile(userId, userCode);

// 2. 初始化 Docker 客户端
DockerClient dockerClient = DockerClientBuilder.getInstance(dockerHost).build();

// 3. 创建容器（带资源限制）
CreateContainerResponse container = dockerClient.createContainerCmd(imageId)
    .withMemoryLimit(memoryLimit)
    .withCpuShares(cpuLimit)
    .exec();

// 4. 编译代码
dockerClient.execStartCmd(execId)
    .withCmd("javac", "Solution.java")
    .exec(new DockerStartResultCallback());

// 5. 执行代码（传入测试用例）
dockerClient.execStartCmd(execId)
    .withCmd("java", "Solution")
    .withAttachStdin(true)
    .exec(new StatisticsCallback());

// 6. 收集输出结果
List<String> outputList = collectOutput();

// 7. 清理容器和文件
deleteContainer();
deleteUserCodeFile();
```

#### 资源限制
- **内存限制**：默认 100MB
- **CPU 限制**：默认 1 核
- **执行时间限制**：默认 5 秒
- **网络隔离**：容器无网络访问

### 3. 判题逻辑

#### 判题流程
```java
// 1. 执行代码，获取输出
SandBoxExecuteResult result = sandboxService.exeJavaCode(userId, userCode, inputList);

// 2. 比对输出结果
boolean passed = resultCompare(userOutput, expectedOutput);

// 3. 检查时间和内存限制
if (result.getTimeUsed() > timeLimit || result.getMemoryUsed() > memoryLimit) {
    // 超时或超内存
    return failResult();
}

// 4. 计算得分
int score = passed ? 100 : 0;

// 5. 保存判题结果
saveUserSubmit(judgeSubmitDTO, result);
```

#### 结果比对
- **精确比对**：逐行比对输出
- **忽略空格**：可配置是否忽略首尾空格
- **部分通过**：支持部分测试用例通过的情况

## 总结

### 架构优势
1. **微服务架构**：模块化设计，易于扩展和维护
2. **服务解耦**：通过消息队列实现异步处理，提高系统吞吐量
3. **统一认证**：Gateway 统一处理身份认证，减少重复代码
4. **高可用性**：服务注册发现、负载均衡、容错机制
5. **性能优化**：Redis 缓存、连接池、异步处理

### 技术亮点
1. **Docker 沙箱**：安全的代码执行环境
2. **异步判题**：RabbitMQ 实现高并发代码提交
3. **全文搜索**：Elasticsearch 提供强大的搜索能力
4. **分布式任务**：XXL-Job 实现定时任务调度
5. **统一配置**：Nacos 配置中心统一管理配置

### 扩展建议
1. **服务监控**：集成 Prometheus + Grafana
2. **链路追踪**：集成 SkyWalking 或 Zipkin
3. **服务限流**：Gateway 集成 Sentinel 实现限流
4. **分布式事务**：集成 Seata 处理分布式事务
5. **多语言支持**：扩展判题服务支持更多编程语言
