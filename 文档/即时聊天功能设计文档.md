
## 一、使用的数据表

本功能使用以下数据表：

### 1. 聊天会话表（`chat_session`）
- **表名**: `chat_session`
- **用途**: 存储学生与企业之间的聊天会话信息
- **主要字段**:
  - `id`: 会话ID（主键）
  - `student_id`: 学生ID
  - `enterprise_id`: 企业ID
  - `job_id`: 关联职位ID（可选）
  - `last_message_id`: 最后一条消息ID
  - `last_message_time`: 最后消息时间
  - `last_message_content`: 最后消息内容（用于会话列表展示）
  - `student_unread_count`: 学生未读消息数
  - `enterprise_unread_count`: 企业未读消息数
  - `status`: 状态（0-已关闭，1-正常）
  - `create_time`: 创建时间
  - `update_time`: 更新时间

### 2. 聊天消息表（`chat_message`）
- **表名**: `chat_message`
- **用途**: 存储聊天会话中的所有消息记录
- **主要字段**:
  - `id`: 消息ID（主键）
  - `session_id`: 会话ID（外键关联 chat_session.id）
  - `sender_id`: 发送者ID
  - `sender_type`: 发送者类型（1-学生，2-企业）
  - `receiver_id`: 接收者ID
  - `receiver_type`: 接收者类型（1-学生，2-企业）
  - `message_type`: 消息类型（text-文本，job-职位信息，image-图片，file-文件，resume-简历）
  - `content`: 消息内容（文本消息或JSON格式的职位信息/简历信息）
  - `related_job_id`: 关联职位ID（当message_type为job时）
  - `is_read`: 是否已读（0-未读，1-已读）
  - `read_time`: 阅读时间
  - `create_time`: 创建时间

### 3. 投诉表（`complaint`）
- **表名**: `complaint`
- **用途**: 存储学生与企业之间的投诉记录（在聊天页面发起投诉时使用）
- **主要字段**:
  - `id`: 投诉ID（主键）
  - `complaint_type`: 投诉类型（1-学生投诉企业，2-企业投诉学生）
  - `complainer_id`: 投诉人ID
  - `complainer_type`: 投诉人类型（1-学生，2-企业）
  - `complained_id`: 被投诉人ID
  - `complained_type`: 被投诉人类型（1-学生，2-企业）
  - `job_id`: 关联职位ID（可选）
  - `title`: 投诉标题
  - `content`: 投诉内容
  - `attachment`: 附件URL（可选）
  - `handle_status`: 处理状态（0-待处理，1-处理中，2-已处理，3-已关闭）
  - `create_time`: 创建时间

### 4. 反馈表（`feedback`）
- **表名**: `feedback`
- **用途**: 存储用户对系统的反馈和建议（在聊天页面发起反馈时使用）
- **主要字段**:
  - `id`: 反馈ID（主键）
  - `user_id`: 用户ID
  - `user_type`: 用户类型（1-学生，2-企业，3-管理员）
  - `feedback_type`: 反馈类型（功能建议、问题反馈、其他）
  - `title`: 反馈标题
  - `content`: 反馈内容
  - `contact_info`: 联系方式
  - `handle_status`: 处理状态（0-待处理，1-已处理，2-已关闭）
  - `create_time`: 创建时间

## 二、业务功能详细描述

### 2.1 会话发起功能

#### 2.1.1 学生端会话发起
- **触发位置**: 职位列表页面、职位详情页面
- **操作流程**:
  1. 学生在浏览职位列表或查看职位详情时，点击"在线咨询"或"发起咨询"按钮
  2. 系统检查该学生与该企业是否已存在针对该职位的会话
  3. 如果不存在，系统自动创建新的会话记录（`chat_session`表）
  4. 如果已存在，系统直接跳转到该会话的聊天页面
  5. 跳转到"线上咨询"页面，并自动选中该会话，右侧显示聊天界面

#### 2.1.2 会话创建规则
- 每个学生与每个企业针对每个职位只能有一个会话（通过 `student_id`、`enterprise_id`、`job_id` 唯一约束保证）
- 如果学生与企业针对某个职位已存在会话，则复用该会话，不再创建新会话
- 会话创建时，初始状态为"正常"（`status = 1`），未读消息数初始化为 0

### 2.2 会话列表功能

#### 2.2.1 学生端会话列表
- **显示位置**: 线上咨询页面左侧
- **列表内容**:
  - 企业头像/Logo
  - 企业名称
  - 职位名称（如果会话关联了职位）
  - 最后一条消息的预览内容（最多显示50个字符）
  - 最后消息时间
  - 未读消息数（红色角标显示）
- **排序规则**: 按最后消息时间倒序排列（最近有消息的会话排在前面）
- **交互功能**:
  - 点击会话项，右侧聊天区域切换到该会话
  - 未读消息数角标显示，点击后查看消息时自动标记为已读
  - 支持会话搜索（按企业名称、职位名称搜索）

#### 2.2.2 企业端会话列表
- **显示位置**: 线上咨询页面左侧
- **列表内容**:
  - 学生头像
  - 学生姓名
  - 职位名称（如果会话关联了职位）
  - 最后一条消息的预览内容（最多显示50个字符）
  - 最后消息时间
  - 未读消息数（红色角标显示）
- **排序规则**: 按最后消息时间倒序排列
- **交互功能**:
  - 点击会话项，右侧聊天区域切换到该会话
  - 未读消息数角标显示，点击后查看消息时自动标记为已读
  - 支持会话搜索（按学生姓名、职位名称搜索）

### 2.3 聊天功能

#### 2.3.1 消息发送
- **消息类型支持**:
  - **文本消息** (`message_type = 'text'`): 普通文本消息
  - **职位信息** (`message_type = 'job'`): 企业可以发送职位信息卡片，学生可以点击查看职位详情
  - **图片消息** (`message_type = 'image'`): 支持发送图片，图片上传到MinIO，content存储图片URL
  - **文件消息** (`message_type = 'file'`): 支持发送文件，文件上传到MinIO，content存储文件URL和文件名
  - **简历消息** (`message_type = 'resume'`): 学生可以发送自己的简历，content存储简历ID或简历信息JSON
- **发送流程**:
  1. 用户在输入框输入消息内容或选择要发送的文件/图片/简历
  2. 点击发送按钮
  3. 前端立即在聊天界面显示消息（乐观更新）
  4. 后端通过RabbitMQ异步处理消息存储
  5. 消息存储成功后，更新会话的最后消息信息
  6. 如果接收者在线，通过WebSocket实时推送消息
  7. 如果接收者不在线，增加其未读消息数

#### 2.3.2 消息接收与显示
- **消息显示规则**:
  - 发送者发送的消息显示在右侧（蓝色气泡）
  - 接收者接收的消息显示在左侧（灰色气泡）
  - 每条消息显示发送时间（超过5分钟的消息显示完整时间，5分钟内的只显示"刚刚"）
  - 消息状态显示：已发送、已送达、已读（双勾图标）
- **消息已读标记**:
  - 当用户打开会话并滚动到底部查看消息时，自动将未读消息标记为已读
  - 标记已读时，更新 `chat_message` 表的 `is_read` 和 `read_time` 字段
  - 同时更新 `chat_session` 表的未读消息数（对应角色的未读消息数减1）

#### 2.3.3 消息历史加载
- **分页加载**: 聊天消息采用分页加载，每次加载20条消息
- **加载时机**: 用户打开会话时，自动加载最新的20条消息；向上滚动时，加载更早的消息
- **排序规则**: 消息按创建时间正序排列（最早的消息在上方，最新的消息在下方）

### 2.4 简历发送功能

#### 2.4.1 学生发送简历
- **触发方式**: 在聊天输入框附近有"发送简历"按钮
- **操作流程**:
  1. 学生点击"发送简历"按钮
  2. 弹出简历选择对话框，显示学生已创建的所有简历
  3. 学生选择要发送的简历
  4. 系统创建一条 `message_type = 'resume'` 的消息
  5. `content` 字段存储简历ID或简历信息的JSON字符串
  6. 消息发送成功后，企业端显示简历卡片，可以点击查看简历详情

#### 2.4.2 简历消息显示
- **企业端显示**: 简历消息以卡片形式显示，包含：
  - 简历标题/名称
  - 学生姓名
  - 简历关键信息预览（学历、专业、工作经验等）
  - "查看完整简历"按钮
- **点击查看**: 企业点击简历卡片，可以查看完整的简历信息

### 2.5 投诉与反馈功能

#### 2.5.1 投诉功能
- **触发位置**: 聊天页面右上角或消息操作菜单中的"投诉"按钮
- **适用角色**: 学生和企业都可以发起投诉
- **投诉对象**:
  - 学生可以投诉当前会话的企业
  - 企业可以投诉当前会话的学生
- **操作流程**:
  1. 用户点击"投诉"按钮
  2. 弹出投诉表单对话框
  3. 表单字段：
     - 投诉标题（必填）
     - 投诉内容（必填，支持多行文本）
     - 关联职位（自动填充当前会话关联的职位，可修改）
     - 附件上传（可选，支持图片、文档等）
  4. 提交投诉后，系统创建投诉记录（`complaint`表）
  5. 投诉记录状态为"待处理"（`handle_status = 0`）
  6. 投诉提交成功后，提示用户"投诉已提交，管理员将在3个工作日内处理"
  7. 投诉提交后，不影响当前聊天会话的继续使用

#### 2.5.2 反馈功能
- **触发位置**: 聊天页面右上角或设置菜单中的"意见反馈"按钮
- **适用角色**: 学生和企业都可以提交反馈
- **操作流程**:
  1. 用户点击"意见反馈"按钮
  2. 弹出反馈表单对话框
  3. 表单字段：
     - 反馈类型（下拉选择：功能建议、问题反馈、其他）
     - 反馈标题（必填）
     - 反馈内容（必填，支持多行文本）
     - 联系方式（可选，用于管理员回复反馈）
  4. 提交反馈后，系统创建反馈记录（`feedback`表）
  5. 反馈记录状态为"待处理"（`handle_status = 0`）
  6. 反馈提交成功后，提示用户"反馈已提交，感谢您的建议"
  7. 反馈提交后，不影响当前聊天会话的继续使用

### 2.6 实时通信功能

#### 2.6.1 WebSocket连接
- **连接建立**: 用户进入线上咨询页面时，自动建立WebSocket连接
- **连接保持**: 连接建立后，定期发送心跳包保持连接
- **断线重连**: 连接断开时，自动尝试重连（最多重试3次）

#### 2.6.2 消息实时推送
- **推送时机**: 当对方发送消息时，如果接收者在线，通过WebSocket实时推送
- **推送内容**: 包含消息的完整信息（消息ID、发送者、内容、类型等）
- **推送处理**: 接收者收到推送后，自动在聊天界面显示新消息，并更新未读消息数

#### 2.6.3 在线状态显示
- **状态标识**: 在会话列表中显示对方的在线状态（在线/离线）
- **状态更新**: 通过WebSocket的心跳机制判断用户是否在线

### 2.7 未读消息管理

#### 2.7.1 未读消息计数
- **计数规则**: 
  - 每个会话维护两个未读消息数：`student_unread_count` 和 `enterprise_unread_count`
  - 当学生发送消息时，`enterprise_unread_count` 加1
  - 当企业发送消息时，`student_unread_count` 加1
- **计数更新**: 
  - 消息发送成功后，立即更新对应角色的未读消息数
  - 消息标记为已读时，对应角色的未读消息数减1

#### 2.7.2 未读消息提示
- **会话列表提示**: 在会话列表项上显示红色角标，显示未读消息数
- **全局提示**: 在导航栏的"线上咨询"菜单项上显示总未读消息数
- **角标清除**: 当用户查看会话并将消息标记为已读后，角标自动清除

### 3.1 整体布局结构

### 3.2 左侧会话列表区域

#### 3.2.1 区域尺寸
- **宽度**: 300px（固定宽度）
- **高度**: 100%（占满AppMain容器高度，AppMain高度为 calc(100vh - 60px)，其中60px为Navbar高度）
- **背景色**: #F5F5F5（浅灰色）

#### 3.2.2 搜索框
- **位置**: 会话列表顶部
- **样式**: 
  - 宽度：100%（占满左侧区域宽度）
  - 高度：50px
  - 内边距：10px
  - 边框：1px solid #E0E0E0
  - 圆角：4px
- **功能**: 
  - 支持按企业名称（学生端）或学生姓名（企业端）搜索
  - 支持按职位名称搜索
  - 实时搜索，输入即搜索

#### 3.2.3 会话列表项
- **高度**: 80px（固定高度）
- **内边距**: 12px
- **边框**: 底部 1px solid #E0E0E0
- **布局**: 横向布局
  - 左侧：头像区域（60px × 60px，圆形）
  - 中间：信息区域（flex: 1）
    - 第一行：对方名称（企业名称/学生姓名）+ 职位名称（如果有，灰色小字）
    - 第二行：最后消息预览（灰色，最多50字符，超出显示省略号）
  - 右侧：时间和未读数区域
    - 最后消息时间（灰色，12px）
    - 未读消息数角标（红色圆形，显示数字，仅在未读数>0时显示）
- **交互效果**:
  - 鼠标悬停：背景色变为 #EEEEEE
  - 选中状态：背景色变为 #E3F2FD（浅蓝色），左侧显示蓝色竖条
  - 点击：切换右侧聊天区域到该会话

### 3.3 右侧聊天区域

#### 3.3.1 聊天头部区域
- **高度**: 60px（固定高度）
- **背景色**: #FFFFFF（白色）
- **边框**: 底部 1px solid #E0E0E0
- **布局**: 横向布局
  - 左侧：对方信息
    - 头像（40px × 40px，圆形）
    - 对方名称（企业名称/学生姓名）
    - 在线状态（绿色圆点 + "在线"文字，或灰色圆点 + "离线"文字）
  - 右侧：操作按钮区域
    - "投诉"按钮（文字按钮，红色）
    - "意见反馈"按钮（文字按钮，蓝色）
    - 更多操作菜单（三个点图标，下拉菜单）

#### 3.3.2 消息显示区域
- **高度**: calc(100% - 聊天头部高度 - 输入区域高度)（占满右侧聊天区域剩余高度）
- **背景色**: #F5F5F5（浅灰色，或聊天背景图片）
- **内边距**: 20px（上下左右）
- **滚动**: 垂直滚动，默认滚动到底部（显示最新消息）
- **消息气泡样式**:
  - **发送者消息**（右侧，蓝色气泡）:
    - 背景色: #1890FF（蓝色）
    - 文字颜色: #FFFFFF（白色）
    - 最大宽度: 70%（避免消息过长）
    - 圆角: 8px
    - 内边距: 10px 15px
    - 对齐方式: 右对齐
  - **接收者消息**（左侧，灰色气泡）:
    - 背景色: #FFFFFF（白色）
    - 文字颜色: #333333（深灰色）
    - 最大宽度: 70%
    - 圆角: 8px
    - 内边距: 10px 15px
    - 对齐方式: 左对齐
  - **时间显示**:
    - 每条消息下方显示发送时间（灰色，12px）
    - 如果连续多条消息在5分钟内，只显示最后一条的时间
  - **消息状态图标**（仅发送者消息显示）:
    - 已发送：单勾（灰色）
    - 已送达：双勾（灰色）
    - 已读：双勾（蓝色）

#### 3.3.3 输入区域
- **高度**: 120px（固定高度，可调整）
- **背景色**: #FFFFFF（白色）
- **边框**: 顶部 1px solid #E0E0E0
- **布局**: 纵向布局
  - **工具栏**（高度：40px）:

## 四、数据流转说明

### 4.1 消息发送流程
```
用户输入消息 → 前端验证 → 发送到后端API → 返回成功（立即响应）
    ↓
后端发送到RabbitMQ队列（chat-message-store-queue）
    ↓
消费者异步处理：
  1. 保存消息到 chat_message 表
  2. 更新 chat_session 表的最后消息信息
  3. 更新未读消息数
  4. 发送到推送队列（chat-message-push-queue）
    ↓
WebSocket推送（如果接收者在线）
```

### 4.2 消息接收流程
```
WebSocket接收消息 → 前端显示消息 → 更新未读消息数
    ↓
用户打开会话 → 加载历史消息 → 滚动到底部 → 标记消息为已读
    ↓
调用后端API标记已读 → 更新 chat_message 表的 is_read 和 read_time
    ↓
更新 chat_session 表的未读消息数（减1）
```

### 4.3 会话创建流程
```
用户在职位页面点击"在线咨询"
    ↓
检查是否存在会话（student_id + enterprise_id + job_id）
    ↓
如果不存在 → 创建新会话（chat_session表）
如果已存在 → 获取现有会话
    ↓
跳转到线上咨询页面，选中该会话
```

## 五、注意事项

1. **数据一致性**: 使用RabbitMQ异步处理消息存储，确保消息不丢失，但需要注意消息顺序问题
2. **性能优化**: 消息历史采用分页加载，避免一次性加载过多消息
3. **实时性**: 使用WebSocket实现消息实时推送，提升用户体验
4. **未读消息数**: 需要准确维护未读消息数，避免数据不一致
5. **会话唯一性**: 通过数据库唯一约束保证每个学生-企业-职位组合只有一个会话
6. **投诉与反馈**: 投诉和反馈功能独立于聊天功能，不影响聊天会话的正常使用
7. **权限控制**: 学生只能查看自己参与的会话，企业只能查看自己参与的会话
8. **消息类型扩展**: 预留了多种消息类型，便于后续扩展（图片、文件、职位、简历等）
