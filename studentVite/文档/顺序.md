## 二、实现顺序建议
按照“可用最小闭环 → 重点业务 → 增强体验 → 增值模块”的原则推进。

### 阶段1（核心闭环 - 账号与基础资料，已部分完成）
1. 登录/注册流程联通（已完成：三端登录、企业/学生注册）
2. 个人/企业资料维护（已完成：学生资料三页、企业资料四页）
3. 基础布局与权限守卫完善（基于 meta.requiresAuth、role，补充路由守卫与重定向）

产出：三端可登录、可维护资料、可进入仪表盘，具备最小可演示能力。

### 阶段2（职位与简历核心业务）
1. 学生端-职位浏览与收藏/详情
   - /student/jobs（列表）
   - /student/job/:id（详情）
   - /student/job/favorite（收藏列表或与职位列表合并显示）
2. 学生端-简历管理（与现有路由对齐）
   - /student/resume（列表）
   - /student/resume/edit/:id?（新增/编辑）
3. 学生端-投递与申请（已接通路由✅，补充交互与联调）
   - /student/resume/delivery（已接通✅）
   - /student/interview/apply（已接通✅）
4. 企业端-职位管理（与现有路由对齐）
   - /enterprise/job（列表）
   - /enterprise/job/add（新增）
   - /enterprise/job/edit/:id（编辑）
   - /enterprise/job/:id（详情）

产出：学生能找岗位→管理简历→完成投递；企业能发布与维护岗位，形成“职位-简历-投递”主链路。

### 阶段3（面试与通知流程）
1. 企业端-面试流程
   - /enterprise/interview/application/list（查看并处理申请）
   - 接口：申请处理、安排面试
   - /enterprise/interview/list、/enterprise/interview/evaluation（评价）
2. 学生端-面试查询与评价查看
   - /student/interview/application（已接通✅）
   - /student/interview/list、/student/interview/evaluation（新增）

产出：面试申请→企业处理→安排面试→评价闭环。

### 阶段4（推荐与数据看板）
1. 学生端-职位推荐：/student/job/recommend
2. 企业端-人才推荐：/enterprise/talent/recommend
3. 管理端/企业端-数据统计与看板
   - /admin/dashboard 补充统计卡与图表
   - /enterprise/statistics/recruitment、/enterprise/dashboard

产出：提升撮合效率与管理洞察。

### 阶段5（咨询、投诉与校园管理等增值模块）
1. 线上咨询（双端）
   - 学生端：/student/consultation/list、/student/consultation/add
   - 企业端：/enterprise/consultation/list、回复能力
2. 投诉与反馈（双端）
   - 学生端：/student/complaint/add、/student/complaint/list
   - 企业端：/enterprise/complaint/add、/enterprise/complaint/list
3. 企业端-校园管理
   - /enterprise/campus/list、/enterprise/campus/job/list
4. 管理端-用户/职位审核与反馈处理（按后端接口完成度逐步补齐）

## 三、落地实施建议（每页共性）
- 统一使用 `api/*` 下已分角色的请求封装与拦截器
- 列表类先做：筛选表单 + 表格 + 分页 + 空态
- 详情类先做：主信息卡片 + 关键字段 + 关联信息（按需分区）
- 表单类先做：前端校验 + 交互反馈 + 禁用重复提交
- 路由守卫：基于 `meta.requiresAuth` 与 `meta.role` 做权限控制与重定向
