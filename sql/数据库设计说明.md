# 校园招聘系统数据库设计说明文档

## 文档说明

本文档详细说明了校园招聘系统数据库的每个表和字段的作用，帮助开发人员理解数据库设计。

**数据库名称**: `campus_hiring_system`  
**字符集**: `utf8mb4`  
**排序规则**: `utf8mb4_unicode_ci`

---

## 一、用户相关表

### 1.1 管理员表 (admin)

**表说明**: 存储系统管理员的基本信息，用于管理员登录、权限管理等功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 管理员ID，主键，自增 |
| username | VARCHAR(50) | 用户名，唯一，用于登录 |
| password | VARCHAR(255) | 密码（加密存储） |
| nick_name | VARCHAR(50) | 昵称，显示名称 |
| real_name | VARCHAR(50) | 真实姓名 |
| phone | VARCHAR(20) | 手机号 |
| email | VARCHAR(100) | 邮箱 |
| head_image | VARCHAR(500) | 头像URL（存储在MinIO） |
| status | TINYINT(4) | 状态：0-已拉黑，1-正常，2-已禁用 |
| remark | VARCHAR(500) | 备注信息 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间，自动设置 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间，自动更新 |

**索引说明**:
- `uk_username`: 用户名唯一索引，确保用户名不重复
- `idx_status`: 状态索引，用于快速查询不同状态的管理员

---

### 1.2 学生表 (student)

**表说明**: 存储学生用户的基本信息、教育背景、技能等，用于学生注册、登录、个人信息管理、职位推荐等功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 学生ID，主键，自增 |
| username | VARCHAR(50) | 用户名，唯一，用于登录 |
| password | VARCHAR(255) | 密码（加密存储） |
| nick_name | VARCHAR(50) | 昵称 |
| real_name | VARCHAR(50) | 真实姓名 |
| phone | VARCHAR(20) | 手机号 |
| email | VARCHAR(100) | 邮箱 |
| head_image | VARCHAR(500) | 头像URL |
| gender | TINYINT(4) | 性别：0-女，1-男 |
| birthday | DATE | 生日 |
| campus_id | BIGINT(20) | 所属校园ID，关联campus表 |
| major | VARCHAR(100) | 专业，用于职位推荐匹配 |
| education | VARCHAR(50) | 学历：专科、本科、硕士、博士 |
| grade | VARCHAR(50) | 年级 |
| skills | VARCHAR(500) | 技能（多个用逗号分隔），用于职位推荐 |
| experience | INT(11) | 工作经验（月），用于职位推荐匹配 |
| expected_salary | DECIMAL(10,2) | 期望薪资，用于职位推荐匹配 |
| expected_location | VARCHAR(200) | 期望工作地点 |
| status | TINYINT(4) | 状态：0-已拉黑，1-正常，2-已禁用，3-待审核 |
| remark | VARCHAR(500) | 备注 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `uk_username`: 用户名唯一索引
- `idx_campus_id`: 校园ID索引，用于按校园查询学生
- `idx_status`: 状态索引
- `idx_major`: 专业索引，用于职位推荐查询

**业务关联**:
- 与 `campus` 表关联，表示学生所属校园
- 与 `resume` 表关联，一个学生可以有多个简历
- 与 `job_application` 表关联，记录学生的职位申请
- 与 `job_favorite` 表关联，记录学生收藏的职位

---

| address | VARCHAR(500) | 企业地址 |
| industry | VARCHAR(100) | 所属行业 |
| scale | VARCHAR(50) | 企业规模：1-50人、51-200人、201-500人、500人以上 |

| website | VARCHAR(200) | 企业官网 |

- `idx_certification_status`: 认证状态索引，用于查询待认证企业

**业务关联**:
- 与 `job` 表关联，一个企业可以发布多个职位

- 与 `interview` 表关联，记录企业安排的面试

## 三、职位相关表

### 3.1 职位类别表 (job_category)

**表说明**: 存储职位分类信息，支持多级分类，用于职位分类管理、职位筛选等功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 类别ID，主键，自增 |
| category_name | VARCHAR(100) | 类别名称 |
| parent_id | BIGINT(20) | 父类别ID（0表示顶级类别），支持多级分类 |
| sort_order | INT(11) | 排序顺序，用于控制显示顺序 |
| status | TINYINT(4) | 状态：0-禁用，1-启用 |
| remark | VARCHAR(500) | 备注 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `idx_parent_id`: 父类别ID索引，用于查询子类别
- `idx_status`: 状态索引

**业务关联**:
- 与 `job` 表关联，职位属于某个类别

---

### 3.2 职位表 (job)

**表说明**: 存储企业发布的职位信息，包括职位要求、薪资待遇、审核状态等，是系统的核心业务表。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 职位ID，主键，自增 |
| enterprise_id | BIGINT(20) | 企业ID，关联enterprise表 |
| category_id | BIGINT(20) | 职位类别ID，关联job_category表 |
| job_name | VARCHAR(200) | 职位名称 |
| job_description | TEXT | 职位描述 |
| required_major | VARCHAR(100) | 要求专业，用于人才推荐匹配 |
| required_skills | VARCHAR(500) | 要求技能（多个用逗号分隔），用于人才推荐 |
| required_education | VARCHAR(50) | 要求学历：专科、本科、硕士、博士 |
| required_experience | INT(11) | 要求工作经验（月），用于人才推荐匹配 |
| work_location | VARCHAR(200) | 工作地点 |
| salary_min | DECIMAL(10,2) | 最低薪资 |
| salary_max | DECIMAL(10,2) | 最高薪资 |
| salary_type | VARCHAR(20) | 薪资类型：面议、月薪、年薪 |
| job_type | VARCHAR(50) | 工作类型：全职、兼职、实习 |
| recruit_count | INT(11) | 招聘人数 |
| view_count | INT(11) | 浏览次数，用于统计 |
| apply_count | INT(11) | 申请次数，用于统计 |
| status | TINYINT(4) | 状态：0-待审核，1-已通过，2-已拒绝，3-已下线 |
| audit_remark | VARCHAR(500) | 审核备注 |
| audit_time | DATETIME | 审核时间 |
| audit_by | BIGINT(20) | 审核人（管理员ID） |
| publish_time | DATETIME | 发布时间 |
| expire_time | DATETIME | 过期时间 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `idx_enterprise_id`: 企业ID索引，用于查询企业发布的职位
- `idx_category_id`: 类别ID索引，用于按类别查询职位
- `idx_status`: 状态索引，用于查询待审核、已通过等状态的职位
- `idx_work_location`: 工作地点索引，用于按地点筛选职位
- `idx_publish_time`: 发布时间索引，用于按时间排序

**业务关联**:
- 与 `enterprise` 表关联，职位属于某个企业
- 与 `job_category` 表关联，职位属于某个类别
- 与 `campus_job` 表关联，职位可以发布到多个校园
- 与 `job_favorite` 表关联，学生可以收藏职位
- 与 `job_application` 表关联，学生可以申请职位
- 与 `resume_delivery` 表关联，学生可以投递简历到职位

**关联查询说明**:
- 查询职位列表时，通常需要关联 `enterprise` 表获取企业名称、Logo等信息
- 查询职位详情时，需要关联 `job_category` 表获取职位类别名称
- 查询学生收藏的职位时，需要关联 `job_favorite` 表获取收藏时间
- 判断职位是否被学生收藏时，需要查询 `job_favorite` 表（student_id + job_id）
- 判断职位是否被学生申请时，需要查询 `resume_delivery` 或 `job_application` 表
- 查询职位关联的校园时，需要关联 `campus_job` 和 `campus` 表

**计算字段说明**:
- `isFavorite`: 判断职位是否被学生收藏，需要查询 `job_favorite` 表（需要传入studentId）
- `isApplied`: 判断职位是否被学生申请，需要查询 `resume_delivery` 或 `job_application` 表（需要传入studentId）

**业务说明**:
- 职位发布后状态为"待审核"，需要管理员审核通过后才能上线
- `required_major`、`required_skills`、`required_experience` 等字段用于人才推荐算法匹配
- `view_count` 和 `apply_count` 用于统计职位的受欢迎程度

---

### 3.3 校园职位关联表 (campus_job)

**表说明**: 存储职位与校园的多对多关联关系，用于实现职位发布到指定校园的功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 关联ID，主键，自增 |
| campus_id | BIGINT(20) | 校园ID，关联campus表 |
| job_id | BIGINT(20) | 职位ID，关联job表 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `uk_campus_job`: 校园ID和职位ID联合唯一索引，防止重复关联
- `idx_campus_id`: 校园ID索引，用于查询某个校园的职位
- `idx_job_id`: 职位ID索引

**业务说明**:
- 一个职位可以发布到多个校园
- 一个校园可以有多个职位
- 企业发布职位时可以选择发布到哪些校园

---

### 3.4 职位收藏表 (job_favorite)

**表说明**: 存储学生收藏的职位信息，用于学生个人中心的收藏管理功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 收藏ID，主键，自增 |
| student_id | BIGINT(20) | 学生ID，关联student表 |
| job_id | BIGINT(20) | 职位ID，关联job表 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 收藏时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `uk_student_job`: 学生ID和职位ID联合唯一索引，防止重复收藏
- `idx_student_id`: 学生ID索引，用于查询学生的收藏列表
- `idx_job_id`: 职位ID索引，用于查询职位的收藏数

**关联查询说明**:
- 查询学生收藏的职位列表时，需要关联 `job` 表获取职位详细信息
- 查询职位收藏数时，需要统计 `job_favorite` 表中对应 `job_id` 的记录数
- 判断学生是否收藏某个职位时，需要查询 `job_favorite` 表（student_id + job_id）

**字段映射说明**:
- 数据库字段 `create_time` 映射为接口字段 `favoriteTime`（收藏时间）

**业务说明**:
- 学生可以收藏感兴趣的职位，方便日后查看和申请
- 一个学生不能重复收藏同一个职位

---

### 3.5 职位申请表 (job_application)

**表说明**: 存储学生对职位的申请记录，用于面试申请与查询功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 申请ID，主键，自增 |
| student_id | BIGINT(20) | 学生ID，关联student表 |
| job_id | BIGINT(20) | 职位ID，关联job表 |
| resume_id | BIGINT(20) | 简历ID，关联resume表（可选） |
| application_status | TINYINT(4) | 申请状态：0-待处理，1-已通过，2-已拒绝，3-已取消 |
| application_time | DATETIME | 申请时间 |
| handle_time | DATETIME | 处理时间（企业处理申请的时间） |
| handle_remark | VARCHAR(500) | 处理备注 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `idx_student_id`: 学生ID索引，用于查询学生的申请记录
- `idx_job_id`: 职位ID索引，用于查询职位的申请记录
- `idx_application_status`: 申请状态索引，用于按状态筛选
- `idx_application_time`: 申请时间索引，用于按时间排序

**关联查询说明**:
- 查询学生的申请记录时，需要关联 `job` 表获取职位名称等信息
- 查询学生的申请记录时，需要关联 `enterprise` 表获取企业名称等信息
- 查询企业的申请记录时，需要关联 `student` 表获取学生姓名、手机号等信息
- 查询申请记录时，可以关联 `interview` 表获取面试安排信息

**字段映射说明**:
- 数据库字段 `application_time` 映射为接口字段 `applicationTime`（申请时间）
- 数据库字段 `handle_time` 映射为接口字段 `handleTime`（处理时间）

**业务说明**:
- 学生可以对心仪的职位进行面试申请
- 申请状态由企业处理，可以查看申请状态及面试安排
- 一个学生可以对同一个职位多次申请（如果之前的申请被拒绝或取消）

---

## 四、简历相关表

### 4.1 简历表 (resume)

**表说明**: 存储学生的简历信息，包括简历文件和个人信息，用于简历管理、简历投递等功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 简历ID，主键，自增 |
| student_id | BIGINT(20) | 学生ID，关联student表 |
| resume_name | VARCHAR(200) | 简历名称 |
| resume_file | VARCHAR(500) | 简历文件URL（PDF、Word等，存储在MinIO） |
| personal_info | TEXT | 个人信息（JSON格式存储） |
| education_background | TEXT | 教育背景（JSON格式存储） |
| work_experience | TEXT | 工作经历（JSON格式存储） |
| project_experience | TEXT | 项目经历（JSON格式存储） |
| skills | TEXT | 技能描述 |
| self_introduction | TEXT | 自我介绍 |
| is_default | TINYINT(4) | 是否默认简历：0-否，1-是 |
| status | TINYINT(4) | 状态：0-已删除，1-正常 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

**索引说明**:
- `idx_student_id`: 学生ID索引，用于查询学生的简历列表
- `idx_status`: 状态索引，用于查询正常状态的简历
- `idx_is_default`: 默认简历索引，用于快速查找默认简历

**业务说明**:
- 一个学生可以创建多个简历
- 可以设置一个简历为默认简历，投递时优先使用
- 简历文件存储在MinIO中，通过URL访问
- JSON格式存储的字段可以灵活存储结构化数据

---

### 4.2 简历投递表 (resume_delivery)

**表说明**: 存储学生向企业投递简历的记录，用于简历管理、简历投递通知等功能。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT(20) | 投递ID，主键，自增 |
| student_id | BIGINT(20) | 学生ID，关联student表 |
| enterprise_id | BIGINT(20) | 企业ID，关联enterprise表 |
| job_id | BIGINT(20) | 职位ID，关联job表 |
| resume_id | BIGINT(20) | 简历ID，关联resume表 |
| delivery_status | TINYINT(4) | 投递状态：0-待查看，1-已查看，2-已通过，3-已拒绝 |
| delivery_time | DATETIME | 投递时间 |
| view_time | DATETIME | 查看时间（企业查看简历的时间） |
| handle_time | DATETIME | 处理时间（企业处理简历的时间） |
| handle_remark | VARCHAR(500) | 处理备注 |
| create_by | BIGINT(20) | 创建人ID |
| create_time | DATETIME | 创建时间 |
| update_by | BIGINT(20) | 更新人ID |
| update_time | DATETIME | 更新时间 |

## 十、数据库设计总结

### 10.1 表关系图

```
用户相关表:
  admin (管理员)
  student (学生) ──→ campus (校园)
  enterprise (企业)

职位相关表:
  job_category (职位类别)
  job (职位) ──→ enterprise (企业)
  job ──→ job_category (职位类别)
  campus_job (校园职位关联) ──→ campus (校园)
  campus_job ──→ job (职位)
  job_favorite (职位收藏) ──→ student (学生)
  job_favorite ──→ job (职位)
  job_application (职位申请) ──→ student (学生)
  job_application ──→ job (职位)

简历相关表:
  resume (简历) ──→ student (学生)
  resume_delivery (简历投递) ──→ student (学生)
  resume_delivery ──→ enterprise (企业)
  resume_delivery ──→ job (职位)
  resume_delivery ──→ resume (简历)

面试相关表:
  interview (面试) ──→ student (学生)
  interview ──→ enterprise (企业)
  interview ──→ job (职位)
  interview_evaluation (面试评价) ──→ interview (面试)

咨询与反馈表:
  consultation (咨询) ──→ student (学生)
  consultation ──→ enterprise (企业)
  complaint (投诉) ──→ student/enterprise (用户)
  feedback (反馈) ──→ user (用户)

消息通知表:
  message (消息) ──→ user (用户)
```

### 10.2 核心业务流程

1. **职位发布流程**:
   - 企业注册/登录 → 企业认证 → 发布职位 → 管理员审核 → 职位上线

2. **职位申请流程**:
   - 学生浏览职位 → 收藏职位 → 申请职位 → 投递简历 → 企业查看 → 安排面试 → 面试评价

3. **简历投递流程**:
   - 学生创建简历 → 投递简历到职位 → 企业收到通知 → 企业查看简历 → 处理简历

4. **面试流程**:
   - 企业安排面试 → 通知学生 → 学生查看面试安排 → 完成面试 → 企业评价

5. **咨询流程**:
   - 学生发起咨询 → 企业收到通知 → 企业回复 → 学生收到通知

### 10.3 设计特点

1. **统一的基础字段**: 所有表都包含 `create_by`、`create_time`、`update_by`、`update_time` 字段，便于审计和追踪

2. **状态管理**: 大部分业务表都有 `status` 字段，用于状态流转和管理

3. **索引优化**: 为常用查询字段建立了索引，提高查询性能

4. **关联设计**: 通过外键关联和索引设计，支持高效的关联查询

5. **扩展性**: 使用 JSON 格式存储灵活数据，使用 `extra_data` 字段存储额外信息

6. **文件存储**: 文件类字段（头像、Logo、简历文件等）存储 URL，实际文件存储在 MinIO

7. **计算字段**: 部分接口返回的计算字段（如 `isFavorite`、`isApplied`）需要通过关联查询计算得出

8. **自动字段**: 部分字段（如 `create_by`、`complainer_type`、`complained_type`）由系统自动设置，不需要前端传入

### 10.4 注意事项

1. **数据一致性**: 
   - 删除用户时需要处理关联数据（软删除或级联处理）
   - 职位下线时需要考虑关联的申请、面试等数据

2. **性能优化**:
   - 大数据量表（如 message、statistics）需要考虑分表或归档策略
   - 频繁查询的统计数据可以使用缓存

3. **安全性**:
   - 密码字段必须加密存储
   - 敏感信息（如身份证号）需要加密或脱敏处理

4. **数据备份**:
   - 定期备份数据库
   - 重要业务数据需要保留历史记录

**职位状态**:
- `0`: 待审核

- `0`: 待处理

### 11.2 常用查询示例

**查询职位列表（关联企业信息、职位类别信息）**:
```sql
SELECT 
    j.*,
    e.enterprise_name,
    e.logo as enterprise_logo,
    jc.category_name
FROM job j
LEFT JOIN enterprise e ON j.enterprise_id = e.id
LEFT JOIN job_category jc ON j.category_id = jc.id
WHERE j.status = 1
ORDER BY j.publish_time DESC;
```

**查询职位列表（判断是否收藏、是否已申请）**:
```sql
SELECT 
    j.*,
    e.enterprise_name,
    e.logo as enterprise_logo,
    CASE WHEN jf.id IS NOT NULL THEN 1 ELSE 0 END as is_favorite,
    CASE WHEN rd.id IS NOT NULL THEN 1 ELSE 0 END as is_applied
FROM job j
LEFT JOIN enterprise e ON j.enterprise_id = e.id
LEFT JOIN job_favorite jf ON j.id = jf.job_id AND jf.student_id = ?
LEFT JOIN resume_delivery rd ON j.id = rd.job_id AND rd.student_id = ?
WHERE j.status = 1
ORDER BY j.publish_time DESC;
```

**查询学生收藏的职位**:
```sql

    jf.create_time as favorite_time

INNER JOIN job j ON jf.job_id = j.id

WHERE jf.student_id = ?
ORDER BY jf.create_time DESC;
```

**查询企业收到的简历（关联学生、职位、简历信息）**:
